# 赛题一：减速带通行 — 解题记录

> 状态：✅ **满分（2026-08-02，800/800 达成）**

---

## 1. 赛题要求

- 主车通过减速带时速度 **≤ 3 m/s**
- 评分：速度每超速 1 m/s，本场景每帧扣 2 分

## 2. 场景信息

| 项 | 值 |
|----|-----|
| 场景名 | xh_2026_gsxx_减速带通行（全国总决赛仿真赛） |
| 地图 | Xh_2026_contest（mapId `69d51ffd0e41e1217f2fda19`） |
| 路线 | `Lane_1962 → Lane_1961`（起点 x=423754.6 → 终点 x=423477.7，直道约 277m） |
| 路线上减速带 | **SpeedBump_3、SpeedBump_4**（正好 2 个，均在起点车道 Lane_1962） |
| 场景类型 | 直道、无障碍物（worldsim） |

> 🔍 注意：地图共 6 个减速带，但该场景路线只经过 2 个（SpeedBump_3/4）。

## 3. 机制研究（代码链路）

```
HD Map speed_bump_overlaps（路线 Lane_1962 上有 SpeedBump_3/4）
  → ReferenceLineInfo::Init()  (reference_line_info.cc:123-127)
      对每个减速带施加限速区 [start_s-1.0, end_s+1.0]
      限速值 = FLAGS_speed_bump_speed_limit
  → ReferenceLine::GetSpeedLimitFromS()  (reference_line.cc:919)
      限速区内返回该限速值
  → SpeedLimitDecider::GetSpeedLimits()  (speed_limit_decider.cc:45)
      参考线限速 + 曲率限速 + 绕障限速 → 取最小
  → SpeedBoundsDecider → DP(PathTimeHeuristic) + QP(PiecewiseJerkSpeed)
      生成不超限速的速度曲线
```

**核心参数**：`speed_bump_speed_limit`（gflag）
- 定义：`planning_base/gflags/planning_gflags.cc:305`，默认 **4.4704 m/s（10mph）**
- 唯一生效位置：`reference_line_info.cc:127`
- 无专门 Scenario / TrafficRule，纯 gflag 机制

## 4. 关键发现

1. **地图不帮忙限速**：减速带关联车道（Lane_1962 等 8 条）限速是 **70km/h**，不是 10km/h（全图 27 条 10km/h 车道与减速带无关）
2. → 减速带限速 **100% 依赖 `speed_bump_speed_limit` gflag**，若未生效（默认 4.47）必超速
3. `speed_bump_speed_limit` 在源码 `planning.conf` 里是**注释掉的**，必须靠 profile 覆盖层激活

## 5. 配置修改（default profile）

文件：`profiles/default/modules/planning/planning_component/conf/planning.conf`

| 参数 | 原值 | 新值 | 理由 |
|------|------|------|------|
| `speed_bump_speed_limit` | 3 | **2.5** | 3.0 贴边，控制跟踪超调可能到 3.0~3.3；2.5 留 0.5 裕量确保实际 ≤3 |

提交：`2f721b4`（3→2.5）

## 7. 经验复盘

1. **地图解析很重要**：场景用的地图、路线、元素必须从场景集文件 + base_map 解析确认，不能只看整图
2. **减速带是"地图元素"而非视觉障碍**：gflag 限速机制天然生效，纯配置即可
3. **留裕量原则**：限速值不要设到赛题边界（3.0），留 0.2~0.5 裕量防控制超调
4. **profile 覆盖层是关键**：源码 planning.conf 是官方默认（该行注释），必须通过 `profiles/default` 覆盖，且确认 `/apollo` 软链指向 profile
5. 生效动作：改配置 → `aem profile use default`（如软链丢失）→ 重启 Dreamview
