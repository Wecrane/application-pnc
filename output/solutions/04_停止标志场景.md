## 7. 云端未到终点的根因：右转弯切内弯（0007 回放分析，2026-08-01）⭐

**用户观察**：云端评测回放中，车辆右转时**切内弯碰路肩** → 仿真停止 → 未到终点。本地未出现。

1. **右转弯段**（frame3900-4200，Lane_1353，半径 8.3m 急弯）：
   - 车辆实际轨迹相对 lane 中心**偏内峰值 0.95m**（带符号 +0.95，内弯侧）

**根因（用户记忆验证）**：**`lane_follow_path` 的 `dddl_weight`（横向三阶导/jerk 权重）**！

**⚠️ 尝试过无效的方案**：

## 7.5 评测仍"右转卡住" → 恢复旧版官方参数（2026-08-01 二次评测）⭐

**用户反馈**：二次评测停止标志场景**右转时卡住**，与本地 0007/1559 验证不一致。

**根因（git 历史 + backup 备份交叉验证）**：
- 旧版官方代码（git `73ff1bc`/`5722120`，用户记忆"没问题"的版本）：
  `ddl_weight=100000 / dddl_weight=500000 / path_reference_l_weight=10000`
- **新版官方基线**（`c9b8b58`，当前源码默认）：
  `ddl_weight=1000 / dddl_weight=50000 / path_reference_l_weight=100`

**修复（profile 覆盖，纯配置）**：恢复旧版官方全套参数
```text
ddl_weight: 100000.0
dddl_weight: 500000.0
path_reference_l_weight: 10000.0
```
> backup 备份（`backup/modules_20260801_093000.tar.gz`）的 `lane_follow_path/conf/default_conf.pb.txt` 即此套参数，用户确认"没问题"。

**待验证**：编译无需（纯配置），`aem profile use default` + 重启 planning，重录回放看右转偏移/间隙。

**用户反馈**：backup 全套（500000/10000）评测**仍右转卡住**且更严重。用户指示：**不再参考旧代码，自由发挥**。

**数据结论**：
- 高 `dddl_weight`（50000/500000）强制路径平滑拉直 → **切内弯**（0007 偏移 0.95m / backup 500000 评测更卡）


**待验证**：`aem profile use default` + 重启，重录回放看右转偏移；评测确认不再卡住。
