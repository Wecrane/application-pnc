### 1.2 车辆行为（1702 实测，expand=2.0 旧配置的"早放行"样本）

- t=29.5 车完全停住，x=423669.81（前端 = 423669.81−3.89 = **423665.92，距人行道东边缘 423664.008 = 1.91m** ✅）
- 主决策：CRUISE → t=6.0 STOP(2 DEST) → t=9.3 **STOP(104 CROSSWALK)** → **t=38.6 104 消失**（STOP 回到 DEST）
- 车 t=39.5 起步（v=0.51），t=42.2 越过人行道
- **但行人 t=44.0 才停** → 车比行人早 4.5s 通过 = **这就是"避让检测失败"的精确失败模式**

**失败原因**：1702 是 expand_s_distance=2.0 时代的记录——扩展 polygon 北边缘 y=4437638.57 < 行人目标 4437639.07，行人 y≈4437638.6（还差 0.5m 走完、仍 0.5m/s 移动）时就出了扩展区 → add5 失效 → 默认逻辑 l≥5.0 且 path 不交叉 → 放行。

### 1.3 1757 记录（当前代码，20-45s 窗口）中 speed_decider 与 crosswalk 的独立决策

```
[plan frame 200-216] 3060_0:stop, CW_Crosswalk_62:stop, DEST:stop   ← 行人入车道，speed_decider STOP
[plan frame 217-244] 3060_0:follow, CW_Crosswalk_62:stop, DEST:stop  ← 行人过车道中央（l≈0.1→1.5），ST 非空 follow 分支
[plan frame 245-253] 3060_0:yield,  CW_Crosswalk_62:stop, DEST:stop  ← 行人将对侧（l≈1.8-2.1）
[plan frame 254+]    (无 3060_0 决策), CW_Crosswalk_62:stop, DEST:stop ← 行人 l>~2.5 后 ST boundary 变空 → speed_decider IGNORE
```

要点：
1. **`3060_0`（真实障碍物）的 STOP/FOLLOW/YIELD 是 speed_decider 给行人个人的决策；`CW_Crosswalk_62`（虚拟障碍物）的 104 STOP 是人行道规则建的。二者是不同障碍物，不经过同一个 `MergeLongitudinalDecision`。**
2. 当前代码（无 add9）在行人 l 稍大于 ~2.5-3.5m（ST boundary 空）后，speed_decider 对行人**完全 IGNORE**——当前只靠 crosswalk 104 STOP 撑着。
3. 104 STOP 的栅栏 x=423665.7（1.75m），**全程稳定**，是真正绑定的停点（BuildPlanningTarget 只取虚拟障碍物的 STOP 做 HARD 目标）。

## 2. 关键问题逐一回答

### Q1：104 STOP 和 ped_fixed STOP 谁主导？MergeLongitudinalDecision 怎么取舍？

- **它们不在同一个障碍物上**，不直接 merge：104 STOP 挂在虚拟障碍物 `CW_Crosswalk_62` 上，ped_fixed STOP 挂在真实行人 `3060_0` 上。
- 停车的**硬目标**由 `BuildPlanningTarget` 决定：它只遍历 **IsVirtual()** 且带 STOP 的障碍物，取 `PerceptionSLBoundary().start_s()` 最小的（s 最小 = 停得最靠后）作为 HARD stop → **人行道赛题里绑定停点就是 crosswalk 的 104 STOP（x=423665.7，1.75m）**。
- 真实行人上的 ped_fixed STOP 只参与该障碍物自身的决策合并与 ST 图约束，**不决定硬停点**。且它在人行道场景记录的 fence（见 Q4）位于 104 STOP **之后**（s 更大），属于非绑定约束。
- `MergeLongitudinalDecision` 对同一障碍物多个 STOP 取 `distance_s` 更小者；但 3060_0 在同一帧通常只有一个纵向决策，不构成竞争。

**结论：人行道赛题由 crosswalk 104 STOP 主导停点；ped_fixed STOP 是"备胎/安全网"，不改变停点。**

### Q2：横穿中段（l 0-3m 在车道上）时，修复方案下车必须停。对吗？

**对。** `HandlePedestrianStop` 的 `l < kClearLateral(3.5)` 分支无条件 STOP（当前代码与修复方案一致），且此时 ST boundary 非空、行人必进 follow/yield 分支 → ped_fixed STOP 保持。crosswalk 104 也同时保持。车停在 1.91m。✅

### Q3：横穿到对侧（l>3m）但仍在移动（0.5m/s）时，会被 ped_fixed STOP 卡住吗？

分两个子问题：

**(a) crosswalk 会不会在这段提前放行？——当前配置下不会。**
- add5 v2：行人**在扩展 polygon 内且 v>0.3 → 无条件 STOP**。
- expand_s_distance=4.0 → 扩展 polygon 北边缘 = 4437636.57+4.0 = **4437640.57 > 行人目标 4437639.07** → 行人**全程都在扩展区内**，移动中 104 STOP 一直保持，直到 v≤0.3（≈t=41）才放行。
- 1702 的早放行（t=38.6）是 expand=2.0 时代的旧记录；改为 4.0 后该路径被堵死。**当前配置下 104 STOP 与 ped_fixed STOP 在同一帧释放（都以 v≤0.3 为门槛），不会出现"104 没了、ped_fixed 还顶着"的窗口。**

**(b) 万一 crosswalk 提前放行（配置回退/异常），ped_fixed 会卡到 3060 停吗？——会，而且这是"正确"行为，不会无限卡。**
- 3060 在 l=8.77m 处**确定会停下**（1702 实测 v=0.00），停后 `l≥3.5 且 v≤0.3` 成立 → ped_fixed 放行。
- 卡住的最长时长 = 行人从"crosswalk 提前放行点"到"完全停止"的时间。即使按最坏的 expand=2.0 场景（t=38.6 放行），行人也在 t=44 停 → **最多多等 ~5s**，不会卡死。
- **这正是修复方案对人行道赛题的正面价值**：它把"crosswalk 一旦放行车就起步"（0005/1702 的失败模式）变成"crosswalk 放行后 ped_fixed 仍顶着直到行人停"，天然兜住 0005/1702 的早通过问题。

### Q4：ped_fixed 的 fence 记在哪？会不会让车蠕进人行道？

- fence 在行人首次进入 follow/yield 分支（l<3.5，约 t≈14-19，车还在减速接近）时记录：`fence_s = 车前端_s + boundary.min_s − 1.75`。此时行人在车前 ~10m 横穿点，**fence 落在 x≈423663.95，位于 crosswalk 停止线（423665.7）之后（s 更大）**。
- 只要 104 STOP 还在（当前配置全程在），104 的 s 更小 → 绑定 → 车停在 423665.92，**永远不会走到 ped_fixed fence**，无蠕进。
- 仅当 104 提前消失（配置回退到 expand=2.0 之类）时，ped_fixed fence 允许车从 423665.92 前蠕 ~2m 到 x≈423663.95（前端正好贴人行道东边缘 423664.0）再等行人停。**这是次要风险**：只在新配置回退时出现，且那时 crosswalk 本就会放行（早通过更糟），ped_fixed 至少保证"等到行人停"。

### Q5：stop_timeout=60 能兜底吗？expand_s_distance=4.0 是什么作用？

- **stop_timeout=60 不能兜底"移动中的行人"。** crosswalk 的计时器只在 `obstacle_speed ≤ 0.3` 且 `!is_on_lane` 时才累计（crosswalk.cc 的 watch-timer 分支）。行人全程 0.5m/s 移动 → **计时器从不累计 → 60s 永不触发**。它只对"已停住 60s 不走"的行人放行。
- 所以"行人永不静止 → 60s 强制放行"是**错误预期**——60s 上限对移动行人无效。但本场景行人必然在 t≈44 停，不需要兜底。
- **expand_s_distance=4.0 的作用**：把 add5 的"移动中无条件 STOP"覆盖到行人完整横穿路径（目标 y=4437639.07 超出原始 polygon 北边缘 4437636.57 有 2.5m，超出 +2m 扩展区还有 0.5m）。4.0 使扩展区北边缘 4437640.57 比目标多出 **1.5m ≈ 3s 的安全余量**——这是 crosswalk 层面防早放行的关键（2.0 时只有 0.57m 余量，1702 实证不够）。

### Q6：人行道赛题会不会因此超时（100s）？

**不会。** 修复方案下人行道场景时间线（当前配置）：

| 事件 | 时间 |
|------|------|
| 车完全停住（前端距人行道 1.91m） | t≈29.5 |
| 行人 v 降到 ≤0.3（104 与 ped_fixed 同时放行） | t≈41 |
| 车起步、越过人行道 | t≈42-45 |
| 行人到终点完全停 | t=44 |
| 车到终点（x=423567.77，距停车点 ~102m，~8m/s） | t≈58-62 |

总用时 **~60s < 100s** ✅。即使 3060 按最慢 0.5m/s 且无加速（纯匀速 31.6s 才横穿到对侧），起步也不晚于 ~50s，仍远小于 100s。

### Q7：id 切换（3060↔3060_0）与 base_id 的作用

- 1757 中行人 id 一直显示 `3060_0`，与 7673↔7673_0 的切换机制同类。**修复方案的 base_id（add12）对 3060 同样必要**：若行人横向 >3.5 的对侧阶段发生 id 切换且无 base_id，fence 查找失败 → ped_fixed STOP 丢失 → 只剩 crosswalk 104 顶着（当前配置下 104 还在，不致命；但若叠加 104 提前放行则直接回到早通过）。
- base_id 使人行道场景的 ped_fixed 安全网在 id 切换时保持连续，属**必须配套项**，不是可选优化。

## 3. 修复方案对人行道赛题影响的最终结论

### 3.1 影响时间线（对比）

| 阶段 | 当前代码（无修复） | + 修复方案 |
|------|------------------|-----------|
| 停点 | crosswalk 104 @1.91m | 不变（104 仍绑定） |
| 横穿中段（l<3.5） | ped_fixed STOP + 104 STOP | 不变 |
| 对侧移动（l>3.5, v=0.5） | boundary 空 → **IGNORE，仅靠 104** | **add9 → ped_fixed 保持 STOP（安全网）** |
| 行人停（t≈44, v=0.00） | 104 放行 → 车走 | 104 与 ped_fixed 同时放行 → 车走 |
| 若 104 意外提前放行 | 车立刻起步（0005/1702 失败模式） | **ped_fixed 继续顶到行人停 → 不再早通过** |

**净效果：修复方案使行人道赛题更安全，不会引入卡死或超时。** 它把"crosswalk 一放行就走"的脆弱点，变成"crosswalk 放行后 ped_fixed 兜底到行人停"。

### 3.2 是否卡死？

**不会。** 卡死需同时满足：ped_fixed 保持 STOP 且行人永不满足 `l≥3.5 且 v≤0.3`。人行道场景 3060 必然走完并在 l=8.77 停（1702 实证 v=0.00）。唯一理论死锁 = 行人停在车道内（l<3.5）且永不动——**本场景不存在**，且该行为在**当前基线 c904b46 就已存在**（l<3.5 分支本就无限 STOP），不是修复方案新增风险。

### 3.3 是否需要"横向≥5m 持续 3s"上限？——**强烈不建议，会直接炸两个赛题**

实测反推（1702 行人曲线）：
- **人行道 3060**：l≥5m 从 t≈32 到 t=44（**持续 ~12s**）。加"l≥5m 持续 3s" → **t≈35 就放行**（行人 y≈4437637、l≈7m、仍 0.5m/s 移动、距终点 2m）→ 车 t≈37-38 越线时行人在人行道上 → **复现 0005/1702 的"避让检测失败"**。
- **停车避让 7673**：l≥5m 从起步后 ~4s 起一路到终点（行人斜走 32m）。加该上限 → 行人仍在 3m/s 移动时就放行 → **"跟车限制检测"再次失败**（正是要修的毛病）。

**结论：任何以"横向达到 X 且持续 N 秒"为判据的上限，在 3060（横穿）与 7673（斜走离道）里都会在行人仍移动时触发，恰好复现两个赛题的早放行失败。** "等完全静止(v≤0.3)"是唯一与评测语义（行人完全离开且停下）对齐、且两场景都已端到端验证（2012b / 1702）的判据。

### 3.4 若要"额外保护"，唯一安全的形态

若担心"行人停在 l<3.5 车道内永不移动"的病态场景（本工程无此赛题），安全兜底应写成：
- **"l<3.5 且 STOP 持续 >N 秒 → 放行"**（针对"卡在车道中央"），而不是"l≥5m 持续 N 秒"。
- 但注意人行道场景 l<3.5 的持续期约 **15s**（t≈14→29），N 必须 >15s 才不误伤；且停车避让 7673 全程 l 快速脱离 3.5，不受影响。
- 即便如此，**建议先不加**：两个受影响赛题的行人都确定会停，加任何兜底都在引入"提前放行"的新风险面。信任已验证的"等静止"判据即可。

## 4. 一句话总结

**修复方案（横向≥3m 且 静止 + add9 boundary 空旁路 + base_id）对人行道赛题是安全的、甚至是增益的**：它不会提前放行、不会卡死、不会超时（车 ~60s 到终点 < 100s），并能在 crosswalk 意外早放行时兜底；**但不要加"横向≥5m 持续 3s"这类横向时间上限**——它会在 3060 仍移动（t≈35）时提前放行，复现当前人行道赛题正修的那个"避让检测失败"。
