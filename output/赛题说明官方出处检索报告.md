## 3. 评分配置与检测项的底层定义（proto 实锤）

### 3.1 评分配置来源：云端共享文件

所有 8 个场景 json 的 `gradingConfigInfo` **完全相同**（已逐一核对）：

```json
"gradingConfigInfo": {
  "baseGradeConfigFile": "grading_system/conf/grading_metrics_default.conf",
  "deselectDefaultMetric": ["Checkpoint"]
}
```

- 检测项/评分指标全部来自云端共享外部配置 `grading_system/conf/grading_metrics_default.conf`（评测系统 simulation 模块），**本地/容器/备份均无此文件**，云端判定逻辑不可得。
- 场景 json 本身**没有任何** `speed_limit`/`collision`/`跟车限制`/`follow` 检测字段 → "跟车限制检测"是**所有场景共用**的评测指标，非本场景独有。

### 3.2 FollowAndBypassCondition（推断 = 评测页"跟车限制检测"）

来源：`output/grading_condition.proto`（容器 `/opt/apollo/neo/src/modules/common_msgs/simulation_msgs/grading_condition.proto`，字段 25），逐字段原文：

```proto
message FollowAndBypassCondition {
  optional apollo.hdmap.Polygon test_range = 1;      // 检测区域多边形
  optional double divide_speed = 2 [default = 3.0];  // 跟车/绕行分界速度（注释"// 3"）
  optional string obstacle_id = 3;                   // 目标障碍物（本场景="7673"行人）
  optional apollo.hdmap.LineSegment end_line = 4;    // 结束线/绕行完成线
  optional bool use_score = 5 [default = false];
  // no single deduction only 100 or 0               // ⭐ 全有全无：只有 100 或 0
}
```

评测框架（`output/sim_grading_metric.proto`）推导的计分语义：
- `Metric{ is_critical=true, require_all_time_pass=true, once_pass_stay_pass=true }` → **任一帧违规 → 整项 0 分**
- `use_score=false` + 注释 "no single deduction only 100 or 0" → **不是"扣 20 分"制，而是 100/0 二值制**

> ⚠️ 注意区分：赛题说明的"**距离<2m 扣 20 分**"是停车距离类扣分（可能对应另一条指标，如 `ObjectOverlapCondition`/距离类检测）；而"**跟车限制检测**"是 100-or-0 的 `FollowAndBypassCondition`。两者不是同一条指标。

### 3.3 判定流程推断（几何逻辑）

```
评测每帧:
  主车在 test_range 多边形内?
    ├─ 否 → 该帧 pass
    └─ 是 → 取 obstacle_id(7673) 速度
             ├─ 速度 < divide_speed=3.0 → 期望"避让/停车等待"（不跟车、不蠕动）
             │     └─ 主车跟车 / 行人未越过 end_line 就起步 → 该帧 fail → 整项 0 分
             └─ 速度 > 3.0 → 期望跟车
```
