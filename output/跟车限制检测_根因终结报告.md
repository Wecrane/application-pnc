## 0. 一句话结论

**「跟车限制检测」= 云端评测器的 `FollowAndBypassCondition` 指标（全有全无 100/0，全程合规）。它判定"自车是否跟在移动中的行人 7673 后面低速行驶"。当前代码让自车在行人横向仅 3.2m、仍以 2.1m/s 移动时就起步通过，被判"跟车" → 0 分。**

真正的放行触发点**不是** `HandlePedestrianStop` 的 `kClearLateral=3.5`，而是 **`boundary.IsEmpty() → AppendIgnoreDecision` 旁路**：行人横向超过约 3.2m 时 ST boundary 变空，自车直接 IGNORE 起步。**只改阈值永远无效。**

## 1. 「跟车限制检测」到底是什么（已从 proto 实锤）

| 项 | 值 |
|----|-----|
| 指标名（评测页显示） | 跟车限制检测 |
| proto 条件 | `FollowAndBypassCondition`（grading_condition.proto 字段 25） |
| 计分 | `use_score=false`，注释原文 **"no single deduction only 100 or 0"** → 全有全无 |
| 指标结构 | `Metric{is_critical=true, require_all_time_pass=true}` → **任一帧违规整项 0 分** |

```proto
message FollowAndBypassCondition {
  optional apollo.hdmap.Polygon test_range = 1;      // 检测区域多边形
  optional double divide_speed = 2 [default = 3.0];  // 跟车/绕行分界速度 = 行人速度 3.0
  optional string obstacle_id = 3;                   // "7673"
  optional apollo.hdmap.LineSegment end_line = 4;    // 绕行完成线（≈行人离开车道线）
  optional bool use_score = 5 [default = false];
  // no single deduction only 100 or 0
}
```

**语义出处**（官方赛事文档《慢速车绕行》）：
> 前车速度 > 3m/s → 主车应**跟随**；前车速度 < 3m/s → 主车应**绕行/避让**。
> 评判标准：低于 3m/s 未绕行（或未通过左侧车道绕行）→ 本场景计 0 分。

**对本场景（行人 7673）的判定流程推断**（证据链收敛）：
```
主车在 test_range 内？
 ├─ 否 → 通过
 └─ 是 → 取 7673 速度（行人移动中，< 3.0 m/s）
      └─ 应"避让/停车等待"（绝不跟车、不蠕动、不在行人未越过 end_line 时起步）
           └─ 自车跟车 / 行人未越过 end_line 就起步 → 该帧违规 → 整项 0 分
```

**通过/失败分界（回放实测模拟）**：
| 回放 | 起步时行人横向 | 结果 |
|------|--------------|------|
| 2209（当前 c904b46） | **3.94m**（仍在移动 2.1m/s） | ❌ 失败 |
| 2054（add9b-revert） | 6.89m（仍在移动） | ⚠️ 边缘 |
| 2012b（add9b，参考"通过"行为） | **7.11m**（行人已完全离开道路） | ✅ 通过 |

→ **分界阈值 ≈ 5~6m = end_line 位置**。行人未越过 end_line（约横向 6m）时自车起步 = 违规。

## 3. 根因分析（三层问题）

### 根因①（核心）：`boundary.IsEmpty() → IGNORE` 旁路

`speed_decider.cc` 循环顶部（L218-222）：
```cpp
if (boundary.IsEmpty() || ...) {
    AppendIgnoreDecision(mutable_obstacle);   // ← 旁路！ST boundary 空 → 直接 IGNORE
    continue;
}
```

- st_boundary_mapper 盒重叠判定阈值 = 车半宽(1.055) + nonstatic_nudge_buffer(0.4) + 行人盒半投影(1.83) ≈ **3.29m**（实测变空点 3.24m）
- 行人横向 > 3.2m → ST boundary 变空 → 循环顶部 `AppendIgnoreDecision` → **自车无约束起步**
- `HandlePedestrianStop` 的 `kClearLateral=3.5` **从未有机会生效**（boundary 空时连 BELOW 分支都进不去）
- 铁证：放行后决策标签为 `-`（IGNORE 的签名，ignore-only 障碍从决策消息中消失），**全程无 `ped_yield_clear`**；放行瞬间横向 3.24m < 3.5

### 根因②：`HandlePedestrianStop` 放行条件只有横向阈值，不管行人是否还在动

即使没有根因①，`obs_l ≥ 3.5 → YIELD` 也会在行人仍移动时放行（历史 c8018da/5af4e4f 的 6.0/8.0 阈值改法同理——8.0m 在 1925 回放中因 boundary 空旁路从未生效）。

### 根因③：fence 用原始 Id() 索引，7673↔7673_0 切换丢 fence

`ped_fixed_fence_s_` 按 `obstacle->Id()` 索引。行人静止（id=7673）→ 移动（id=7673_0）切换时，若恰逢 boundary 空，`HandlePedestrianStop` 无法按 7673 查到 fence → 回退 ignore → STOP 闪烁（2109 回放实锤）。2209 中因切换时 boundary 非空、HandlePedestrianStop 对 7673_0 重记了栅栏才未闪烁。

## 4. 用户两大假设的验证

### 假设A："起步后重新触发 FOLLOW（车辆跟随）" → **数据不支持**
- add7 之后所有版本（2054/2109/2209）**全程 0 次 FOLLOW**，0 次 YIELD
- 代码层面：`MakeObjectDecision` 中 PEDESTRIAN 的所有路径（IsStatic/CheckIsFollow/else）都走 `HandlePedestrianStop` 固定栅栏，**不存在给行人下发 FOLLOW 的路径**
- "跟车"不是 planning 的 FOLLOW 决策，而是**评测器几何检测**（自车在行人未离开时起步 = 被判"跟车"）

### 假设B："轨迹线朝右偏一下" → **真相是路径线跳变，不是车跳**
- **车身物理完全笔直**（2209：13m 行程横向仅 2.3cm，yaw≈-0.001）
- "朝右偏" = **LANE-BORROW↔SELF 路径切换闪烁**：停车阶段走左借道（`regular/leftforward`，路径偏左），起步瞬间 0.7s 内切换 3 次（BORROW→SELF→BORROW→SELF），轨迹线从偏左跳回居中 = 视觉"朝右偏一下"
- 借道闪烁发生在车起步前 ~7.6s（车静止），且是"线跳"非"车跳"，**不可能触发跟车限制**（该指标要求车移动）
- 借道复发根因：path_decider 的 `front_static_obstacle_cycle_counter` 慢衰减（每帧 -1）+ id 迟清除（counter<-2 才清），释放瞬间 6 项借道检查立即重新通过；阻塞者其实是护栏 5530（非行人）

| 版本 | 做法 | 结果 |
|------|------|------|
| add8 (c904b46) 当前 | kClearLateral=3.5 + YIELD 放行 | ❌ boundary 空旁路先触发，3.5 未生效 |
| 5af4e4f/ee910fd | 阈值 8.0 + 要求静止 | ❌ 阈值永不生效（boundary 空） |
| add9 (4cbdf7d) | boundary 空时对 fence 行人调 HandlePedestrianStop | ⚠️ 方向对，但放行仍 3.0m 横向、不要求静止 → 车蠕动尾随 |
| add9b (d475dab) | IsStatic 行人也走 HandlePedestrianStop | ⚠️ 2012b 等行人完全静止才放行 = **正确行为**，但 2012/2014 卡死（横向 3.0 且静止条件在某帧不满足→蠕动→又停） |
| add9c/add10 | path_decider 跳过行人 + fence 用 ST s | ❌ **撞飞**（PerceptionSL s 噪声 60m → STOP 点错位 54m；path_decider blocking STOP 覆盖） |
| add11 (ca11ae6) | 放行改 IGNORE + path_decider continue | ⚠️ 本地无 FOLLOW 行为正常，但评测仍失败（放行仍早，行人仍移动） |
| add12 (7abb9a6) | fence 用 base_id | ⚠️ 消除闪烁，但 2109 记录窗口只到 60s 误判"卡死"；放行仍早 |
| add13 (de34a95) | 位置兜底复用栅栏 | ⚠️ 过度工程 |

**教训**：
1. `PerceptionSLBoundary().s` 有噪声（差 60m）→ fence 优先用 ST boundary 的 s，boundary 空才用 obs_s
2. path_decider 不能给行人建 blocking STOP（会用感知 SL 算错位置）
3. 行人 id 会 7673/7673_0 切换 → fence 必须 base_id
4. **放行必须"横向离开 且 静止"，且要堵 boundary 空旁路**——两者缺一不可

## 6. 修复方案（add14，五处改动，全部集中在 speed_decider）

### 改动1：堵 boundary 空旁路（L218-222）
对 **PEDESTRIAN 且 `ped_fixed_fence_s_` 有记录（按 base_id 查）** 的障碍，boundary 空时改调 `HandlePedestrianStop` 而不是直接 ignore。路边散步者（横向 3~6m 从未进车道近处、无记录）保持 ignore。

### 改动2：放行条件 = 横向≥3.0m **且** 速度≤0.3
- 新增 `kMaxStopSpeed = 0.3`（用 `Perception().velocity()` 的模长，不用 IsStatic——无 prediction 延迟）
- `kClearLateral` 3.5 → **3.0**（小阈值避免卡死"停在横向 3~6m 的静止行人"；真正的门槛是静止判据）
- 放行用 **IGNORE**（不用 YIELD）：YIELD 保留"让行"语义 → 起步朝行人微偏（add11 已证）；IGNORE 同时把行人移出 path_decider 静态作用域，防止其停止后重建 blocking STOP
- fence 记录：boundary 非空用 `adc_sl_boundary_.end_s() + boundary.min_s() + stop_dist`（可靠），boundary 空才用 `obs_s + stop_dist`（add10 教训）

### 改动3：fence 全链路 base_id（speed_decider.cc + .h）
`base_id = id.substr(0, id.find('_'))`，record/find/erase 全用 base_id（无 `_` 时天然等于全串）。

### 改动4（可选，建议先不加）：超时兜底
"横向≥8m 持续 5s 未静止 → 放行"。**实测不建议加**："横向 X 持续 N 秒"判据都会在行人仍移动时触发（人行道 3060 l≥5m 持续 12s 仍 0.5m/s 移动）→ 复现避让检测失败。等完全静止是唯一与评测语义对齐的判据。若要兜底，安全形态是"l<3.5 持续 >15s"（异常行人永久堵路场景），本工程两场景都不触发。

### 改动5（可选）：静态行人 fence 记录（add9b）
IsStatic 分支行人也可调 HandlePedestrianStop 记录 fence，覆盖"静态→移动+恰逢 boundary 空"的极端切换。本场景 2209 未触发（切换时 boundary 非空），建议作为稳健性补充。
