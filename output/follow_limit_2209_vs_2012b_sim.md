- 主车/行人状态逐帧（10Hz）：`t, ped(x,y,v), veh(x,v), 决策`
- 几何量（道路近直，heading≈-0.003）：
  - 行人横向偏移 `lat ≈ ped_y − 4437610.77`（已验证：restart_precise 的 SL lat 与该差一致）
  - 纵向距离 `lon ≈ ped_x − veh_x`（正值=行人在主车前）

## 4. 最优推断：评测器真实逻辑

### 4.1 真实 proto 字段（`output/grading_condition.proto:258`）

```proto
message FollowAndBypassCondition {
  optional apollo.hdmap.Polygon test_range = 1;   // 检测区域多边形
  optional double divide_speed = 2 [default = 3.0]; // = 行人目标速度 3.0
  optional string obstacle_id = 3;                 // = "7673"
  optional apollo.hdmap.LineSegment end_line = 4;  // 线段：障碍"放行"线
  optional bool use_score = 5 [default = false];
  // 注释：no single deduction only 100 or 0  → 二值判定（通过/不通过），非逐帧扣分
}
```

### 4.2 最优推断（与三份回放全兼容）

> **在 `test_range` 内：行人 7673 正在移动（v>ε）且尚未越过 `end_line`（≈行人横向 6m，即完全离开道路）时，若主车位于行人后方并以低于 `divide_speed`(3.0) 的速度行驶 → 判为"跟车" → 该指标直接判失败（0 分）。行人越过 `end_line` 后限制解除。**

依据（证据链）：
1. **`end_line` 是唯一判别量**：2209 与 2012b 都有"行人移动中主车低速尾随"，但 2209 行人 lat −3.5~−5.4（未过线）失败，2012b 行人 lat −6.6~−11（已过线）通过。判别点精确落在 lat ∈ (3.94, 6.78)，与 end_line≈6m 一致。
2. **`divide_speed=3.0` = 行人速度**：语义 = "低于行人速度=跟在后面（Follow，禁止）；≥行人速度=超越（Bypass，允许）"。2209 主车 t=55.5~57.5 以 0.04~2.9 m/s（<3.0）尾随 1.8s → 触发；2012b 主车也在 0.9~5.4s 以 <3.0 行驶，但行人已过线 → 不触发。
3. **必须"行人移动"门控**：接近阶段（2209 t=17–37.5）主车对**静止**行人减速蠕动 0.5–3.0 m/s 持续 6.5s——若门控不含"障碍移动"，正常停车也会误判（指标无法通过），故必须有障碍移动条件。
4. **二值判定**（proto 注释 "only 100 or 0"）：只要出现过一次"跟车"帧即判失败。2209 触发帧为 **t=55.5~55.7**（首次 v>0.05/0.2，行人 lat −3.55/−3.70、v 2.16/2.20、lon 21.1/21.4），此后 1.8s 内持续处于跟车态 → 指标 0 分。
5. **与 git 修复方向吻合**：用户释放阈值 3.5m→6.0m→8.0m→要求行人静止，正是逐步逼近"行人必须越过 end_line≈6m 才能放行"。

### 4.3 判定逻辑最终表述（可验证的等价形式）

```
每帧（10Hz，test_range 内）:
  if ped(7673).moving 且 ped 未越过 end_line(≈lat 6m) 且 ped 在主车前方:
      if 0 < veh_v < divide_speed(3.0):        # 低速跟在行人后
          → 判"跟车限制"失败（0/100）
```
2209 触发时刻 t≈55.5（veh_v=0.09 起即触发），2012b 永不触发（行人先过线）。

## 5. 附：对"正确起步条件"的建议（仅研究结论，不改代码）

- 本回放根因 = `HandlePedestrianStop::kClearLateral=3.5`（c904b46）放行过早：行人 lat 仅 3.5m（道路边缘、仍在移动）就释放 STOP → 主车起步即落入"跟车"。
- 若要过"跟车限制"：放行条件应改为**行人横向 ≥ ~6m（越过 end_line 语义）**，即用户 git 历史中的 6.0m 阈值方向（而非 3.5m），且 6m 是数据上"通过/失败"的分界（3.94→失败、6.78→通过）。
