# 第2章 评分规则（怎么拿满分）

## 2.1 机制（源码确认）

- 每 0.1s 一帧，逐帧评估；每个 metric 从 100 起扣，`require_all_time_pass`（**任何一帧违规 = 该题不 PASS**）
- 场景分 = 100 − Σ各题扣分；总分 = 4 场次平均
- 硬失败（delta=100）：压线/越线/移动中太近/碰撞/行人未走完就动

## 2.2 每题的满分做法

### 🚨 巡航题（CruiseSpeedLimit + AccelerationLimit）
- 速度 ≤ **3.0556 m/s**（超 1 m/s 扣 2 分/帧）；加速度 **[−3, 2]**（超 1 扣 1 分/帧）
- **满分做法**：`cruise=2.5`（留 0.55 裕量，实测峰值 2.456 欠冲无超调）→ 双达标

### 🚨 人行道停车（crosswalk，6am/7pm）
- 只在行人占用横道时评分；**合格停车 = 停稳后车头距横道 [1.0, 1.5]m**
- 停 <1.0 扣 20；压横道/越线/移动中距 <1.0/行人未走完就动 = **硬失败 100**
- **满分做法**：`stop_distance=1.25`（中值）+ 提前减速 + 等行人完全走完

### 🚨 红灯停车（red_light，6pm/7am）
- 只在红灯时评分；**合格 = 停稳后车头距停止线 [1.0, 1.5]m**
- **满分做法**：`stop_distance=1.25`；红灯停稳、绿灯才走

### 🚨 减速带限速（RoadSpeedLimit）
- **车辆包围盒**与多边形区域重叠即生效（车头一进就算！），区域内 ≤ **1.0 m/s**（超 1 扣 2 分/帧）
- 区域：6am[24.7,30.5] / 6pm[26.9,32.6] / 7am[23.0,28.9] / 7pm[23.5,29.1]
- **满分做法**：插件区段限速 `0.7`（留 0.3 裕量）+ `forward_buffer 8m` 提前降速 + `backward 5/8m` 覆盖尾段

## 2.3 扣分速查表（一页纸）

| 动作 | 扣分 |
|------|------|
| 巡航超速 >3.0556 | 2 分/帧/m/s |
| 加速度出 [−3,2] | 1 分/帧/m/s² |
| 减速带区域超速 >1.0 | 2 分/帧/m/s |
| 停车 <1.0m（人行道/红灯） | **20 分/次** |
| 停车 >1.5m | 0（可继续接近） |
| 压横道 / 越线 / 移动中 <1.0m / 行人未走完就动 / 碰撞 | **100 硬失败** |
| cruise / upper 越界 [1.5,5.1] | **整次判 0** |
| 超时 >120s | 0 分 |

## 2.4 苏州 10 次实测的教训（score_history，7/28）

- **red_light 10/10 满分** → 红灯题最容易
- **road_speed 从不满分**（0~63）→ **超速是最大丢分源**（巡航 5.0 所致）
- crosswalk 一半 100 一半 0 → 停车时机/距离不稳
- **结论：攻克限速（cruise 2.5）+ 停车（1.25）即满分**

## 4.1 🔴 必改 12 项（不改必扣分/必挂）

### ① `default_cruise_speed`：5.0 → **2.5**（planning.conf）【不改 = 巡航题 0 分】

- **控制什么**：**全局默认目标巡航速度**——速度规划里在没有其他限制（限速区/停车/跟车等）时，车"默认开多快"。由 planning_component 读取，作为速度优化器的目标 v（巡航段的速度设定值）
- **评分依据**：巡航题（CruiseSpeedLimit）全程逐帧判定速度 ∈ `[-0.5, 3.0556] m/s`，超速每 1 m/s 扣 2 分/帧，`require_all_time_pass`（任何一帧违规整题不 PASS）
- **数值推导**：5.0 超上限 1.944 → `ceil(1.944)×2 = 4 分/帧` → **25 帧（2.5 秒）就把 100 分清空** → 巡航题必 0 分。苏州 10 次实测 road_speed 从不满分（0~63）就是这个根因
- **为什么 2.5 不是 3.0**：3.0 实测速度峰值 3.14~3.16（加速爬坡过冲）→ 会超 3.0556 扣分；2.5 距上限 0.5556，且实车实测 2.5 巡航峰值 **2.456（欠冲无超调）** → 实际裕量 ≈0.6
- **副作用**：总时长 70~91s（<120s）✓；减速更平缓反而降低加速度扣分风险

### ② crosswalk `stop_distance`：0.10 → **1.25** 【不改 = 人行道停车扣 20 + 压线硬失败风险】

- **控制什么**：**crosswalk 规则建 STOP 时，停车线相对横道前缘的距离**——即人行道停车时"车头要停在斑马线前多远"。由 crosswalk.cc `BuildStopDecision(..., config_.stop_distance(), ...)` 在横道前缘往前推此距离生成 STOP 点
- **评分依据**：人行道题合格停车 = **停稳后车头距横道 [1.0, 1.5]m**；停 <1.0 扣 20；压入横道/移动中距 <1.0 = **硬失败 100**
- **数值推导**：原始 0.10 → 192840 实测停车 **0.26m**（<1.0）→ 扣 20；且 0.26 离压线（0m）极近 → 稍有偏差就硬失败
- **为什么 1.25**：区间 [1.0,1.5] 中值；仿真标定 1:1（stop_distance=1.75 → 实测 1.78，误差仅 0.03m）
- **前提说明**：此参数在 crosswalk 规则**触发时**生效（行人被识别为 PEDESTRIAN）；**若不触发**（UNKNOWN），由第 4.2 节 `min_stop` 兜底 → 两者构成双保险

### ③ traffic_light `stop_distance`：0.10 → **1.25** 【不改 = 红灯贴线必挂】

- **控制什么**：**traffic_light 规则建 STOP 时，停车线相对停止线的距离**——红灯时"车头要停在停止线前多远"。由 traffic_light.cc 在停止线（signal overlap）前推此距离生成 STOP 点
- **评分依据**：红灯题合格 = **停稳后车头距停止线 [1.0,1.5]m**；压线/红灯越线 = **硬失败 100**
- **数值推导**：原始 0.10 → 停车 0.1m = 贴线 → 压线硬失败风险极高
- **与 crosswalk 不同**：信号灯规则用**信号灯状态**（不依赖障碍物类型）→ **必然生效**，没有 UNKNOWN 问题 → 这一项是红灯题唯一的停车控制点

### ④ crosswalk `stop_timeout`：3.0 → **30.0** 【不改 = 行人横穿慢必硬失败】

- **控制什么**：**crosswalk STOP 建立后，等待行人的最长时长**——超过此时长行人还没走完，规则放弃 STOP 放行（决定车"最多等行人多久"）。由 crosswalk.cc 的 stop_timeout 比较（行人占用计时）
- **评分依据**：合格停车后**行人未清空就移动 = 硬失败 100**
- **源码机制**：crosswalk STOP 建立后，行人占用超过 stop_timeout → 规则放弃 STOP 放行
- **数值推导**：6am/7pm 行人横穿 8.2m，最慢 **0.5 m/s → 需 16.4s > 3s** → 3s 后规则放行 → 车在行人未清空时移动 → **硬失败 100**。6am/7pm 都有 0.5m/s 的行人（6841/6844/6845）→ 必踩
- **为什么 30**：16.4s × 约 2 倍裕量；120s 限时内 70s 流程 + 30s 等待仍 <120s ✓

> **这 4 项控制什么**：同 crosswalk 区段，只是围绕**信号灯停止线（Signal_1/Signal_6）**建限速带。6am/6pm 的减速带评分区（Δy24.7~30.5 / 26.9~32.6）= Signal 位置，必须开此区段。

| `traffic_light_backward_buffer` | 1.0→**8.0** | **限速带终点（停止线后延伸多远）**——何时解除限速 | ⭐**最关键**。`signal overlap 在停止线位置`（比信号灯本体提前 1.1~1.35m）。评分区尾 6am 30.53 / 6pm 32.61。backward=5 → 区段尾 29.71/31.84 < 评分区尾 → **车尾出区前恢复加速 → 尾部 0.8m 缺口 → 9~10 帧超速 → 扣 20~40 + require_all_time_pass FAIL**。backward=8 → 区段尾 32.71/34.84 > 评分区尾（裕量 1.4~2.2m）→ 全覆盖。**必改** |
| `traffic_light_limit_speed` | 1.0→**0.7** | **限速带内的目标速度** | 留裕量（同 crosswalk）。**必改** |

## 4.2 🟡 强烈建议 2 项（有它更稳，防御实车日志实测的坑）

### ⑬ `min_stop_distance_obstacle`：0.0 → **0.8**（planning.conf）【不加有实测风险，加了无害】

- **控制什么**：**speed_decider 建 STOP 时，停车点相对障碍物的纵向距离**——即"车要停在障碍物（任何类型，含行人/车辆/锥桶）前多远"。由 speed_decider.cc `CreateStopDecision(..., -FLAGS_min_stop_distance_obstacle)` 统一作用于 static / cross / too_close 所有 STOP 分支；`max_stop_distance_obstacle` 只影响转弯（MinRadiusStopDistance），不在此列
- **为什么是"强烈建议"而不是"必改"**：它只在 crosswalk 规则**不触发**时兜底。若现场行人被识别为 PEDESTRIAN（crosswalk 正常触发），`stop_distance=1.25` 生效，speed_decider 对已有 STOP 决策的障碍物**跳过** → min_stop 不参与。**所以交叉口触发时它不碍事，只有交叉口不触发时它救命**。
- **实车实测风险（为什么必须考虑）**：15 个实车日志 **STOP reason 只有 DESTINATION，从无 CROSSWALK** → crosswalk 规则从不建 STOP（横穿行人被感知为 **UNKNOWN 类型**，crosswalk.cc 类型检查仅收 PEDESTRIAN/BICYCLE → 直接 return false）→ 停车全靠 speed_decider 兜底。原始 0.0 = **停行人前 0m** → 实测停车 **0.26/0.32/0.36/0.62m 全 <1.0 → 每场都扣 20**
- **数值推导**：设 0.8 → 停车 = 0.26~0.62 + 0.8 = **1.06~1.42m 全达标**。⚠️ **不能设 1.25**（0.26+1.25=1.51 超上限 1.5）
- **副作用（可控）**：静态障碍物/跟车 too_close 也停 0.8m 前（比 0 更安全）；终点 DESTINATION 有独立决策不受影响；限速/加速度题无关
- **结论**：**这就是我们比"改几个就满分"的队伍多改的核心原因**——我们用自己的日志实测到了这个坑，1 行成本换停车题双保险，值得

### ⑭ crosswalk `expand_s_distance`：0.0 → **6.0**【帮触发 + 防急刹，两重收益】

- **控制什么**：**crosswalk 检测区的大小**——把横道 polygon 向四周扩展多少米，决定"行人进入多大范围才被 crosswalk 规则判定为需要停车"。由 crosswalk.cc `CheckStopForObstacle` 中 `polygon().ExpandByDistance(config_.expand_s_distance())` 判定行人位置是否在扩展后区域内（硬门槛，不在即 skip）
- **为什么"强烈建议"**：帮助 crosswalk 规则**触发**。实测 PEDESTRIAN 行人在横道旁 **l=-3.5~-3.9**（expand=0 的检测区 l=[-2.4,2.0] 不含）→ expand=6 后检测区 l=[-8.4,8.0] 覆盖 → 这类行人若进横道会触发 crosswalk 建 STOP（用 1.25）
- **防急刹收益**：提前 6m 检测 → 提前平缓减速：2.5²/(2×6)=**0.52 m/s²**（远低于加速度边界 −3）
- **局限（所以不是必改）**：对 UNKNOWN 类型无效（类型检查在前）；只对 PEDESTRIAN/BICYCLE 有效
- **副作用**：无（扩大检测区不会误停——crosswalk 还有 stop_strict/loose 横向判定 + 减速可控）

## 4.3 🟢 可选 3 项（可不改，改了纯属加保险）

### ⑮ `planning_upper_speed_limit`：5.0 → **4.5**【不改合法，改了消边界风险】

- **控制什么**：**速度规划的绝对速度上限**——所有轨迹点速度的硬天花板（无论巡航/限速/其他，速度优化都不能超过它）。由 planning gflag 读取，作为速度优化器的 v 约束上界；同时被评分系统 `cruise_speed_check` 检查合法性
- **为什么"可不改"**：5.0 **本身合法**（铁律 [1.5,5.1] 内），不改**不会判 0**
- **改的理由（纯保险）**：5.0 距上限 5.1 **仅 0.1**，任何配置解析/四舍五入误差都可能越界 → **整次判 0（一票否决）**。降 4.5 后距上限 0.6，彻底消除该风险
- **副作用**：无（4.5 远高于巡航 2.5，仅加速天花板，行为无差异）
- **建议**：改（1 行成本换一票否决保险）；**不改也合法**。→ PLAN_B/D 改 4.5，PLAN_A/C 保持 5.0

### ⑯ crosswalk `stop_strict_l_distance`：1.0 → **4.0**【低速下不改无风险，改是防御极端】

- **控制什么**：**crosswalk 规则 SKIP 放行的横向阈值**——行人横向距离 l 大于此值且急刹评估通过（stop_deceleration ≥ max_stop_deceleration）时，车"可以不建 STOP 直接通过"。由 crosswalk.cc 的 SKIP 判断使用
- **它防什么**：SKIP 提前放行（车急刹能停住 + 行人横向远 → 不建 STOP 直接冲过去）
- **为什么"可不改"**：SKIP 触发需**两个条件同时满足**：①`stop_deceleration ≥ 4.0`（急刹评估）②行人横向 l > strict。我们 **cruise 2.5 低速 + expand=6 提前 6m 减速** → 实际减速度 0.52~1.2 m/s² **<< 4** → **SKIP 分支根本不会进入** → strict=1 也不会误放行
- **改 4.0 的理由**：防御极端场景（行人突然冲出 + 车距近 + 高速）→ l>1 就可能放行；4.0 > 横道宽 3.9m → 行人只要在横道上永不 SKIP
- **结论**：可改可不改。PLAN_B/D 改，PLAN_A/C 不改（保守）

### ⑰ crosswalk `stop_loose_l_distance`：1.5 → **5.0**【与默认行为几乎一致，纯保险】

- **控制什么**：**crosswalk 行人横向分档的"弱停档"上界**——行人横向 l 落在 [strict, loose] 之间时，规则按"弱停"处理（仅当行人路径与车交叉才停车）；l ≥ loose 视为无冲突放行。由 crosswalk.cc 的分档判断使用
- **它管什么**：行人横向三档：l<strict 强停 / strict≤l<loose 弱停（仅路径交叉才停）/ l≥loose 放行

- **它管什么**：行人横向三档：l<strict 强停 / strict≤l<loose 弱停（仅路径交叉才停）/ l≥loose 放行
- **为什么"可不改"**：行人**横穿必然与车路径交叉**（is_path_cross=true）→ 即使 loose=1.5，弱停档也会停（路径交叉兜底）→ 行为与 loose=5.0 几乎一致
- **改 5.0 的理由**：官方默认 + 与 strict=4 构成「强停区(≤4) + 弱停区(4~5)」双保险
- **结论**：可改可不改。PLAN_B/D 改，PLAN_A/C 不改

# 第5章 为什么这么调（实车日志发现链，理解"17 项"的来历）

> 完整历程：`审查报告_20260805.md`（8 轮审查）。以下是结论链。

## 5.1 发现 1：限速题是最大失分源
- 苏州 10 次评分 **road_speed 从不满分**（0~63）
- 根因：实车 `cruise=5.0` 远超 3.0556 → 每帧扣 4 分 → 秒清空
- **对策**：`cruise 5.0→2.5`、`upper 5.0→4.5`（铁律保险）

## 5.2 发现 2：停车距离不可控（🔴 最重要）
- **15 个实车日志 STOP reason 只有 `DESTINATION`，从无 `CROSSWALK`** → crosswalk 规则**从不建 STOP**
- 停车全靠 **speed_decider 兜底**：停行人前 `min_stop_distance_obstacle`（实车 0）→ 实测停车 **0.26/0.32/0.36/0.62m**（全 <1.0 扣 20）
- **真根因（第八轮）**：横穿行人被感知为 **UNKNOWN 类型**（192840 日志 28793/28780）→ crosswalk.cc 类型检查（仅 PEDESTRIAN/BICYCLE）失败 → **expand 再大也不触发**
- **对策**：
  - `min_stop_distance_obstacle 0→0.8`（speed_decider 停任意类型行人前 0.8m → 停车 1.06~1.42m 达标）—— **真正兜底**
  - `expand 0→6`（对 PEDESTRIAN 类型行人扩大检测，帮 crosswalk 触发）
  - `stop_distance 0.1→1.25`（规则触发时的目标值）
  - ⚠️ **min_stop 不能 1.25**（0.26+1.25=1.51 超上限）

## 5.3 发现 3：减速带区段尾部缺口
- 评分用**整车盒**判定（车尾出区才算通过）
- `traffic_light backward=5` 时 6am/6pm 尾部缺口 0.79~0.81m → 9-10 帧超速 → 扣 20-40 + require_all_time_pass FAIL
- **对策**：`backward 5→8`（裕量 1.4~2.2m）；crosswalk 区段 5.0 已够（实测 0.49 达标）

## 5.4 发现 4：control 无超调（推翻前期假设）
- control.log 无控制量；planning v 实测 **2.5 巡航峰值 2.456（欠冲）** → cruise 2.5 裕量更足（~0.6）
- "超调 0.14-0.16"假设不成立（3.14-3.16 是加速爬坡经过点）
- 停车精度 +0.16~+0.52m → ±0.1m 不现实 → 现场实测后微调

## 5.5 其他验证
- 海驾场 10 次评分（旧版 4 题制）：**crosswalk/red_light 停车要求同为 [1.0,1.5]m**（与新版一致）→ 无"4 题制 [0,2.0]"这回事
- `skip_overlap_stop_check=true`（实车 conf）→ path_decider 不兜底横向 STOP → 停车完全靠 speed_decider + 规则
- 本地评分复现器：192840 停车 0.26→1.25 平移 = 80→100 分（零仿真闭环验证）
