# 第2章 评分规则（怎么拿满分）

## 2.1 机制（源码确认）

- 每 0.1s 一帧，逐帧评估；每个 metric 从 100 起扣，`require_all_time_pass`（**任何一帧违规 = 该题不 PASS**）
- 场景分 = 100 − Σ各题扣分；总分 = 4 场次平均
- 硬失败（delta=100）：压线/越线/移动中太近/碰撞/行人未走完就动

## 2.2 每题的满分做法

### 🚨 巡航题（CruiseSpeedLimit + AccelerationLimit）
- 速度 ≤ **3.0556 m/s**（超 1 m/s 扣 2 分/帧）；加速度 **[−3, 2]**（超 1 扣 1 分/帧）
- **满分做法**：`cruise=2.5`（留 0.55 裕量，实测峰值 2.456 欠冲无超调）→ 双达标

### 🚨 人行道停车（crosswalk，6am/7pm）
- 只在行人占用横道时评分；**合格停车 = 停稳后车头距横道 [1.0, 1.5]m**
- 停 <1.0 扣 20；压横道/越线/移动中距 <1.0/行人未走完就动 = **硬失败 100**
- **满分做法**：`stop_distance=1.25`（中值）+ 提前减速 + 等行人完全走完

### 🚨 红灯停车（red_light，6pm/7am）
- 只在红灯时评分；**合格 = 停稳后车头距停止线 [1.0, 1.5]m**
- **满分做法**：`stop_distance=1.25`；红灯停稳、绿灯才走

### 🚨 减速带限速（RoadSpeedLimit）
- **车辆包围盒**与多边形区域重叠即生效（车头一进就算！），区域内 ≤ **1.0 m/s**（超 1 扣 2 分/帧）
- 区域：6am[24.7,30.5] / 6pm[26.9,32.6] / 7am[23.0,28.9] / 7pm[23.5,29.1]
- **满分做法**：插件区段限速 `0.7`（留 0.3 裕量）+ `forward_buffer 8m` 提前降速 + `backward 5/8m` 覆盖尾段

## 2.3 扣分速查表（一页纸）

| 动作 | 扣分 |
|------|------|
| 巡航超速 >3.0556 | 2 分/帧/m/s |
| 加速度出 [−3,2] | 1 分/帧/m/s² |
| 减速带区域超速 >1.0 | 2 分/帧/m/s |
| 停车 <1.0m（人行道/红灯） | **20 分/次** |
| 停车 >1.5m | 0（可继续接近） |
| 压横道 / 越线 / 移动中 <1.0m / 行人未走完就动 / 碰撞 | **100 硬失败** |
| cruise / upper 越界 [1.5,5.1] | **整次判 0** |
| 超时 >120s | 0 分 |

## 2.4 苏州 10 次实测的教训（score_history，7/28）

- **red_light 10/10 满分** → 红灯题最容易
- **road_speed 从不满分**（0~63）→ **超速是最大丢分源**（巡航 5.0 所致）
- crosswalk 一半 100 一半 0 → 停车时机/距离不稳
- **结论：攻克限速（cruise 2.5）+ 停车（1.25）即满分**

# 第5章 为什么这么调（实车日志发现链，理解"17 项"的来历）

> 完整历程：`审查报告_20260805.md`（8 轮审查）。以下是结论链。

## 5.1 发现 1：限速题是最大失分源
- 苏州 10 次评分 **road_speed 从不满分**（0~63）
- 根因：实车 `cruise=5.0` 远超 3.0556 → 每帧扣 4 分 → 秒清空
- **对策**：`cruise 5.0→2.5`、`upper 5.0→4.5`（铁律保险）

## 5.2 发现 2：停车距离不可控（🔴 最重要）
- **15 个实车日志 STOP reason 只有 `DESTINATION`，从无 `CROSSWALK`** → crosswalk 规则**从不建 STOP**
- 停车全靠 **speed_decider 兜底**：停行人前 `min_stop_distance_obstacle`（实车 0）→ 实测停车 **0.26/0.32/0.36/0.62m**（全 <1.0 扣 20）
- **真根因（第八轮）**：横穿行人被感知为 **UNKNOWN 类型**（192840 日志 28793/28780）→ crosswalk.cc 类型检查（仅 PEDESTRIAN/BICYCLE）失败 → **expand 再大也不触发**
- **对策**：
  - `min_stop_distance_obstacle 0→0.8`（speed_decider 停任意类型行人前 0.8m → 停车 1.06~1.42m 达标）—— **真正兜底**
  - `expand 0→6`（对 PEDESTRIAN 类型行人扩大检测，帮 crosswalk 触发）
  - `stop_distance 0.1→1.25`（规则触发时的目标值）
  - ⚠️ **min_stop 不能 1.25**（0.26+1.25=1.51 超上限）

## 5.3 发现 3：减速带区段尾部缺口
- 评分用**整车盒**判定（车尾出区才算通过）
- `traffic_light backward=5` 时 6am/6pm 尾部缺口 0.79~0.81m → 9-10 帧超速 → 扣 20-40 + require_all_time_pass FAIL
- **对策**：`backward 5→8`（裕量 1.4~2.2m）；crosswalk 区段 5.0 已够（实测 0.49 达标）

## 5.4 发现 4：control 无超调（推翻前期假设）
- control.log 无控制量；planning v 实测 **2.5 巡航峰值 2.456（欠冲）** → cruise 2.5 裕量更足（~0.6）
- "超调 0.14-0.16"假设不成立（3.14-3.16 是加速爬坡经过点）
- 停车精度 +0.16~+0.52m → ±0.1m 不现实 → 现场实测后微调

## 5.5 其他验证
- 海驾场 10 次评分（旧版 4 题制）：**crosswalk/red_light 停车要求同为 [1.0,1.5]m**（与新版一致）→ 无"4 题制 [0,2.0]"这回事
- `skip_overlap_stop_check=true`（实车 conf）→ path_decider 不兜底横向 STOP → 停车完全靠 speed_decider + 规则
- 本地评分复现器：192840 停车 0.26→1.25 平移 = 80→100 分（零仿真闭环验证）

## 6.1 必改 vs 可不改（回答"是不是改太多了"）

- **🔴 必改 12 项**：cruise 2.5 + 停车 1.25×2 + timeout 30 + 限速插件 8 项 —— **不改必扣分/必挂**

- **情报解读**："其他队改几个满分" = 场景常规时核心参数少；"限速扣 1 分" = 进区减速加速度或区段边缘 → 我们 forward8 + limit0.7 已覆盖

| 3 | 红灯触发识别（6pm/7am） | DreamView Signal_1 红/绿正常 | 查感知注入 |
| 4 | 巡航峰值 | ≤3.0556（期望 2.456） | cruise 2.2 |
| 5 | 放行时行人位置 | 已出横道 | 感知偏差 >1.6m 才触发，概率低 |
| 6 | 全程加速度 | ∈[−3,2] | 检查减速起点 |

## 7.3 红线（绝对不能碰）

1. **`cruise` 和 `upper` 必须在 [1.5, 5.1]**（越界整次 0 分）
2. **不要编译**（只改配置；改完只重启对应模块）
3. **不要动 control**（实车已验证无超调）
4. **改配置前先备份**：`cp planning.conf planning.conf.bak_时间戳`
