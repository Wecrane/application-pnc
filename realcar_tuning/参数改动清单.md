## 二、逐文件详细改动（含注释，直接可上传）

### ① `planning_component/conf/planning.conf`（gflags）

```text
# ⚠️ 评分铁律 [1.5,5.1]：planning_upper_speed_limit 千万别调高（>5.1 越界整次判 0）
# 原 5.0 距上限 5.1 仅 0.1，稳版降至 4.5（巡航目标 2.5 远低于此，仅作加速天花板，无行为影响）
--planning_upper_speed_limit=4.5          # ⭐ 修改（5.0→4.5 加裕量）
# 原 5.0 → 2.5（评分 cruise ≤3.0556；3.0 实测速度峰值 3.14-3.16 会超速；2.5 距上限 0.5556 留大裕量）
--default_cruise_speed=2.5                # ⭐ 修改
```

| 参数 | 原值 | 新值 | 修改依据 |
|------|------|------|---------|
| `--default_cruise_speed` | 5.0 | **2.5** | 评分 cruise 限速 ≤3.0556m/s；实车日志速度峰值 3.14-3.16（超 3.0556）→ 3.0 配置仍可能超调超速；取 2.5 距上限 0.5556、扣超调 0.16 仍剩 ~0.4 裕量（稳）；同时降低停车接近速度（减速度更小，防 SKIP + 防加速度扣分） |
| `--planning_upper_speed_limit` | 5.0 | **4.5** | 铁律 [1.5,5.1]，越界整次判 0；原 5.0 距上限 5.1 仅 0.1 太贴，降 4.5 留 0.6 裕量（实车 cruise 评分固定 3.0556 不跟随此参数，4.5 只作参考线天花板，巡航 2.5 无影响） |

#### 🔍 详细论证

**1.1 `--default_cruise_speed`：5.0 → 2.5（稳版）**

**① 评分依据（Metric B：CruiseSpeedLimit）**
- 巡航限速范围 **max +3.0556 m/s（11km/h）/ min −0.5 m/s**，且 `is_critical + require_all_time_pass` —— **全程每一帧**超速都扣分，任何 1 帧违规=该 metric 不 PASS
- 扣分：`over = speed − 3.0556`，每超 1 m/s 扣 **2 分/帧**（`delta = ceil(over/1) × 2`）

**② 原值 5.0 的量化危害**：
- 5.0 − 3.0556 = **1.94 m/s** → 每帧扣 `ceil(1.94)×2 = 4 分` → 巡航全程约 30s≈300 帧，**第 25 帧（约 2.5s）就把 100 分清空**
- 这正是苏州 score_history **10 次实测 road_speed 最高仅 63、多次 0 分** 的根因（5.0 巡航直接判死）

**③ 控制层超调证据（为什么 3.0 也不够）**：
- 实车日志实测：**速度峰值 3.14–3.16 m/s**（当时 planning 目标 3.0）→ 控制层超调 **0.14–0.16 m/s** 是实锤
- 若取 3.0：3.0 + 0.16 = **3.16 > 3.0556 → 必然超速扣分**（is_critical 全程必达标）

**④ 取 2.5 的裕量推导（稳版）**：
- 2.5 → 3.0556 之间留 **0.5556 m/s**；扣除最坏控制超调 0.16 → 仍剩 **≈0.40 m/s 安全裕量**（2.8 版仅剩 0.095，太贴极限）
- 若现场实测超调更大（坡度/载重变化），仍可再降（2.5→2.2），但**不得低于铁律下限 1.5**

**⑤ 铁律校验**：`default_cruise_speed=2.5 ∈ [1.5,5.1]` ✓；`planning_upper_speed_limit=4.5 ∈ [1.5,5.1]` ✓（cruise_speed_check scope=all，越界整次判 0；4.5 距上下限分别 3.0 / 0.6，极安全）

**⑥ 附加收益（连锁优化）**：
1. **停车接近速度更低**：2.5 m/s 接近停止线 → 制动距离 2.5²/(2×3.0)=1.04m，实际减速度 <2.0 → 不触发 crosswalk SKIP（需 decel≥4.0）、不超加速度边界 [−3,2]
2. **减速带区降速更从容**：2.5→0.7 只降 1.8 m/s，配合 forward_buffer=8m 平缓降速
3. **加速度扣分风险降低**：低速巡航加减速变化率小（Metric A：1 分/帧/m/s²）

**⑦ 时间预算验证**：全程 103m @2.5 m/s ≈ 41s（不含停车），+ 人行道等待 ≤30s + 红灯等待 ≤25s = **约 71s < 120s 限时** ✓
**⑧ 红灯题时序验证**：Signal_1 灯序 绿(3s)→红(25s)→绿(100s)，车 2.5 m/s 行驶 60m 需 **24s**，落在红灯窗口（出发后 3–28s）✓ 仍能赶上红灯停车

**1.2 `--planning_upper_speed_limit`：5.0 → 4.5（稳版，加裕量）**

**① 铁律**：cruise_speed_check 检查范围 **[1.5,5.1]**、`scope=all` —— **越界整次评测判 0 分（一票否决）**。原 5.0 距上限 **5.1 仅 0.1**，太贴极限；降 4.5 后距上下限分别 3.0 / 0.6，极安全
**② 为什么实车赛可以降（与仿真关键区别）**：仿真评测 SpeedLimit 跟随 `min(地图, upper)`（降 upper=降评测限速=自锁陷阱）；**实车赛 cruise 评分是固定 3.0556**（Metric B 源码判定 `speed−3.0556`，不读此参数）→ 降 upper 不影响任何评分线
**③ 行为影响为零**：它是参考线限速天花板 `min(地图 5.5556, 4.5)=4.5`，巡航目标 2.5 远低于 4.5 → 正常行驶完全不受限；仅当 default_cruise_speed 意外失效/被误改时，车最多 4.5，也不会触犯 5.1 铁律（兜底保险）
**④ 结论**：4.5 = 纯安全收益，无副作用

### ② `traffic_rules/crosswalk/conf/default_conf.pb.txt`

```text
stop_distance: 1.25          # 原 0.10 → 1.25（评分停车 [1.0,1.5]m）
max_stop_deceleration: 4.0
min_pass_s_distance: 1.0
expand_s_distance: 6.0       # 原 0.0 → 6.0（提前识别行人防急刹）
stop_strict_l_distance: 4.0  # 原 1.0 → 4.0（官方默认；防 SKIP 提前放行：SKIP 条件需 l>此值）

```

| 参数 | 原值 | 新值 | 修改依据 |
|------|------|------|---------|
| `stop_distance` | 0.10 | **1.25** | 评分停车 [1.0,1.5]m；0.1 停太近 → 扣 20 分 + 急刹 4.9-6.9 m/s² 双扣分（日志实证）；标定 1:1（仿真 1.75→1.78）取中值 |
| `expand_s_distance` | 0.0 | **6.0** | 行人提前进入检测区 → 车提前平缓减速，减速度 <3.0 不扣加速度分 |
| `stop_timeout` | 3.0 | **30.0** | 行人未走完不提前放行（评分 require_all_time_pass，提前走=硬失败风险） |
| `stop_strict_l_distance` | 1.0 | **4.0** | 🆕 回归 crosswalk.cc 源码：SKIP 条件 = `stop_deceleration≥4.0 且 l>stop_strict_l_distance` → 实车 1.0 时行人 l>1.0 就可能被放行（冲斑马线=评分硬失败 100）。调回官方默认 4.0：①扩大强停区 ②SKIP 需 l>4.0（行人几乎都在保护内） |
| `stop_loose_l_distance` | 1.5 | **5.0** | 🆕 回归源码：l≥loose 时仅路径交叉才停。实车 1.5 太小，行人横穿斑马线中段（l 1.5-3.9）可能落入弱保护。调回官方默认 5.0（≥斑马线宽 3.9m）确保全程必停 |
| `max_stop_deceleration` | 4.0 | 4.0（不改） | SKIP 阈值；靠巡航 2.5 + stop_distance 1.25 提前减速避免触发（不调大，调大允许急刹扣加速度分） |

#### 🔍 详细论证

**2.1 `stop_distance`：0.10 → 1.25**

**① 评分依据（CrosswalkStop，只在有行人/非机动车占用人行横道时检测）**：
- 停稳后距横道 **[1.0, 1.5]m = 合格**；**< 1.0m 扣 20 分**；**> 1.5m 不扣分**（可继续接近微调）
- 移动中距横道 <1.0m / 压入横道 / 合格停车后行人未清空就移动 = **硬失败 100**

**② 原值 0.10 的量化危害**：
- 0.1m = 车头几乎贴横道线才停 → 车头前伸（front_edge_to_center=3.62m）+ 控制误差 → **几乎必然 <1.0m 扣 20 分**，甚至压入横道硬失败 100
- 苏州 score_history：crosswalk 一半 0 分（16:19/16:29/17:48/17:57 场次）→ 与 stop_distance=0.1 停太近/急刹高度相关

**③ 标定依据（为什么 1.25 直接映射实际停车距离）**：
- 仿真标定 **1:1**：stop_distance=1.75 → 实际车头距横道 **1.78m**（误差仅 0.03m）→ 该参数值 ≈ 实际停车距离
- 取 **1.25 = [1.0,1.5] 中值**：实际 1.25±0.1 → [1.15,1.35] ⊂ [1.0,1.5] ✓，上下各留 0.25 裕量
- **宁远勿近**：>1.5 不扣分可继续接近；<1.0 直接扣 20（评分细则明确战术）

**④ 附加收益**：1.25 比 0.1 提前 1.15m 建 STOP → 2.5 m/s 下减速度 ≈1.2 m/s²，不超加速度边界、不触发 SKIP

**2.2 `expand_s_distance`：0.0 → 6.0**

**① 评分依据**：Metric A 加速度 [−3,2]（1 分/帧/m/s²，require_all_time_pass）+ CrosswalkStop“移动中距横道<1.0m 硬失败”
**② 机制**：把横道检测区**向前扩展 6m** → 行人/横道提前进入 planning 视野 → 车提前 N 米开始平缓减速
**③ 原值 0.0 的危害**：行人/横道到停止线处才被发现 → 2.5 m/s 下发现即需急刹（减速度可能 <−3）→ 加速度扣分 + 停车过冲（可能压线）
**④ 数值推导**：
- 2.5→0 最小制动距离 = 2.5²/(2×3.0) = **1.04m**（3.0 m/s² 边界内）
- expand 6m 提供 6m 减速空间 → 实际减速度 ≈ 2.5²/(2×6) = **0.52 m/s²，远低于边界**，平缓无扣分
- 6.0 依据：覆盖“行人提前进入横道”的检测提前量 + 最慢横穿场景的从容减速

**2.3 `stop_timeout`：3.0 → 30.0**

**① 评分依据**：**合格停车后行人未清空就移动 = 硬失败 100**（require_all_time_pass 全程必达标）
**② 机制**：crosswalk STOP 建立后，超过 stop_timeout 行人仍占用 → 规则放弃 STOP/放行
**③ 原值 3.0 的危害**：行人横穿速度 0.5–1.0 m/s、斑马线宽 3.9m → 最慢横穿需 **3.9/0.5 = 7.8s > 3s** → 3s 超时后行人仍在横道 → 规则放行 → 车在行人未清空时移动 → **硬失败 100**
**④ 取 30.0**：30s ≫ 7.8s（约 4 倍裕量），即使行人中途停留/折返也足够；120s 限时内 37s 巡航 + 30s 等待 = 67s < 120s ✓

**2.4 `stop_strict_l_distance`：1.0 → 4.0（🆕 二轮审查新增）**

**① 源码机制（crosswalk.cc 回归确认）**：**SKIP（直接放行跳过横道）条件 = `stop_deceleration ≥ 4.0 且 行人横向距离 l > stop_strict_l_distance`** —— 评估“急刹能停住”且“行人离得够远” → 不建 STOP 直接通过
**② 原值 1.0 的危害**：行人横向 **>1.0m** 即满足 SKIP 放行条件 → 行人还在横道边缘（横向 1–3.9m 全程）时车冲过去 → **压横道/撞行人硬失败 100**
**③ 取 4.0（官方默认）**：**4.0 > 斑马线宽 3.9m** → 行人只要还在横道上（横向 0–3.9m）就**永不触发 SKIP** → 必停 ✓
**④ 与 2.5 巡航双保险**：SKIP 需 decel≥4.0（急刹评估），2.5 低速接近时实际减速度 ≈1.2 <4.0 → SKIP 分支根本不会进入
**⑤ 证据**：苏州 crosswalk 0 分场次很可能就是 SKIP 提前放行（车冲横道）

**2.5 `stop_loose_l_distance`：1.5 → 5.0（🆕 二轮审查新增）**

**① 源码机制（crosswalk.cc）**：行人横向分三档 —— **l < strict：强停**；**strict ≤ l < loose：弱停**（仅路径交叉才停）；**l ≥ loose：无冲突放行**
**② 原值 1.5 的危害**：行人横穿中段（横向 1.5–3.9m）落入“弱停”档 → 路径不交叉就放行 → 车在行人仍在横道中间时通过 → 硬失败风险
**③ 取 5.0（官方默认）**：**5.0 ≥ 斑马线宽 3.9m + 行人身体缓冲** → 行人横穿全程（0–3.9m）都在必停区；与 strict 4.0 构成「强停区(≤4.0) + 弱停区(4.0–5.0)」双保险，行人任何时刻都在保护内 ✓

**不改项说明**：`max_stop_deceleration=4.0` 是 SKIP 阈值（靠巡航 2.8 + 提前减速避免触发；调大=允许急刹扣加速度分）；`min_pass_s_distance=1.0` 为通行距离阈值，正常不动。

#### 🔍 详细论证

**先讲核心机制（5.0 全组共同依据）**

**① 减速带评分区 = 精确多边形，car_polygon（车头！）进区即判定**：

| 场次 | 区域 Δy | 覆盖元素 |
|------|--------|---------|
| 6上午 | 24.7–30.5m | Signal_1（常绿） |
| 6下午 | 26.9–32.6m | Signal_6（常绿） |
| 7上午 | 23.0–28.9m | Crosswalk_1 |
| 7下午 | 23.5–29.1m | Crosswalk_1 |

**② 区域内限速 [-0.5, 1.0] m/s**，超速每超 1 m/s 扣 **2 分/帧**，`is_critical + require_all_time_pass`（车头一进区域即算，不是车中心！）

**③ 地图事实**：4 张图 **speed_bump=0、stop_sign=0** → 插件 speed_bump 区段无 overlap 可挂（**开了也无效**）；减速带区恰好 = 第 1 个信号灯/人行道位置 → **必须用 crosswalk / traffic_light 区段限速覆盖**

**④ 插件机制**：TrafficRule `AddSpeedLimit(起, 终, limit)` 施加参考线限速 → planning 目标速度降为 limit_speed（与减速带 gflag 同款机制，SpeedLimitDecider → DP/QP 生效）

**⑤ 判定细节**：car_polygon 含整车 → forward_buffer 保证进区前降速，backward_buffer 保证出区后才恢复（防车尾还在区内就加速）

**5.1 `crosswalk_enabled`：false → true**

- 7上午/7下午减速带区（Δy 23–29m）= **Crosswalk_1 位置** → 必须开人行道区段
- **不开的量化危害**：车以 2.5 巡航进入区域 → 超速 1.5 m/s → 每帧扣 `ceil(1.5)×2=4 分` → 区域宽 5.9m ≈ 2.4s ≈ 24 帧 → **扣约 96 分**（且 require_all_time_pass 直接不 PASS）
- **与停车题无冲突**：7下午停车题 Crosswalk_5（Δy 60.8m）也在 crosswalk 区段限速内 → 0.8 低速接近横道 → 停车更稳（兼容，甚至有益）

**5.2 `crosswalk_limit_speed`：1.0 → 0.7（稳版）**

- 区域内限速 **≤1.0 才合格**；原 1.0 **零裕量** → 控制超调/误差瞬间超速
- 取 0.7：留 **0.3 裕量**（低速控制超调 <0.1，0.7+0.1=0.8 < 1.0 极安全；0.8 只留 0.2 偏贴极限）
- 0.7 足够低（评分只限负向 −0.5，0.7 距其 1.2，不会触发“速度过低”）；附：主办方 proto 默认 3.0，实车已改 1.0，本清单再降 0.7

**5.3 `crosswalk_forward_buffer`：1.0 → 8.0**

- **提前 8m 开始限速** → 车头进评分区前已降到 0.8 → 进区瞬间不超速
- 数值推导：2.5→0.7 降 1.8 m/s，用 0.5 m/s² 减速需 1.8²/(2×0.5)=**3.24m**；8m > 2.5 倍距离 → 实际减速度 ≈ 1.8²/(2×8) = **0.20 m/s²**，平缓不扣加速度分
- buffer=1.0 的危害：进区前 1m 才降 → 车头进区时速度仍 2.5+ → 超速扣分

**5.4 `crosswalk_backward_buffer`：1.0 → 5.0（第五轮审查修正：2.0→5.0）**

- **🚨 真实赛题几何实测**（base_map + 场景 json 逐点核算）：

| 场次 | 减速带元素 | 元素 Δy | 评分区 Δy | backward=2 时限速终点 | 缺口 |
|------|-----------|---------|----------|---------------------|------|
| 6上午 | Signal_1(常绿) | 27.54 | 24.7-30.5 | 29.55 | **0.95m** |
| 6下午 | Signal_6(常绿) | 27.92 | 26.9-32.6 | 29.93 | **2.67m** |
| 7上午 | Crosswalk_1 | 25.76 | 23.0-28.9 | 28.78 | 0.12m |
| 7下午 | Crosswalk_1 | 25.76 | 23.5-29.1 | 28.74 | **0.36m** |

- **危害量化**：车在限速区终点恢复 2.5 加速，但评分区尾部仍在判定（car_polygon 车头进区即算）。6下午缺口 2.67m：0.7 加速 2.67m → v=√(0.49+2×2×2.67)=**3.35 m/s ≫1.0** → 每帧扣 4 分 + require_all_time_pass 直接不 PASS；6上午 0.95m → v≈2.07>1.0；7下午 0.36m → v≈1.39>1.0
- **backward=5.0 验证**：6下午限速终点 27.92+5=**32.92 > 32.6** ✓；6上午 32.54>30.5 ✓；7下午 31.74>29.1 ✓ → 4 场次全覆盖 + 出区余量
- **时间代价**：出评分区后多限速 2-4m @0.7 ≈ 3-6s，总预算仍 ~70s < 120s ✓

**5.5–5.8 `traffic_light` 四参数（enabled / limit_speed / forward / backward）**：逻辑与 5.1–5.4 完全相同，仅覆盖对象不同：

- `traffic_light_enabled`：6上午/6下午减速带区（Δy 25–33m）= **Signal_1/Signal_6（常绿）** → 开信号灯区段
- `limit_speed 0.7 / forward 8.0 / backward 5.0(crosswalk) / 8.0(traffic_light)`：crosswalk 区段 5.0 已实车验证够（7am/7pm）；traffic_light 区段 8.0 覆盖 6am/6pm 停止线 overlap 缺口
- **与红灯停车题兼容**：6下午/7上午停车题也是 Signal_1 红灯 → 插件 0.8 限速与红灯停车**不冲突**（红灯停稳在区内，距停止线 1.25m，区段限速 ≤1.0 同时满足）→ 限速题与停车题同时通过 ✓

**不改项说明**：`speed_bump_*`（4 图 speed_bump=0，无 overlap 无效）；`junction_*`（4 图无相关路口限速需求，保持 false）
