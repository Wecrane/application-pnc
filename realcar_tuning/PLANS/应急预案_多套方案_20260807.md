# 应急预案：多套配置方案 + 现场决策树（2026-08-07 赛前）

> **背景**：明天（8/7）比赛，今天（8/6）其他队伍已赛。情报：①有人说"改几个参数就满分"；②有人说"不管怎么改限速都会扣 1 分"。**担忧**：我们改的参数（17 项）是否太多、反而出问题？
>
> **结论先行**：
> 1. **真正"必改"只有 12 项**（cruise 2.5 + 停车距离 1.25×2 + 限速插件 8 项 + timeout 30），其余是**防御性可选**（应对实车日志发现的 UNKNOWN/感知偏移/SKIP 等坑）。
> 2. 其他队"改几个就满分" = 场景常规时核心参数少；但我们**实车日志实测**过 crosswalk 有"不触发 → 停车 0.26m 扣 20"的风险 → `min_stop_distance_obstacle=0.8` 是**值得加的一道保险**（只加 1 项，副作用可控）。
> 3. "限速扣 1 分"大概率是**进区减速瞬间的加速度**或**区段边缘**问题 → 已用 forward=8 + limit 0.7 覆盖；若现场仍扣，用 PLAN_D（limit 0.6 / forward 10）。
> 4. **建议现场默认启用 PLAN_C（停车兜底，14 项）**，首圈验证后按决策树调整。PLAN_B（17 项全防御）作为"追求零风险"备选。

## 一、必改 vs 可不改 分级

> 📖 **17 项逐项详细论证**（为什么改/不改的后果/副作用/数值推导，非一句话版）见 `最终阅读版_20260807.md` 第 4 章。本节是现场速查版。

### 🔴 必改（不改必扣分 / 必挂）—— 12 项

| # | 参数 | 原始→新值 | 不改的后果 |
|---|------|----------|-----------|
| 1 | `default_cruise_speed` | 5.0→**2.5** | 巡航 5.0 远超 3.0556 → 巡航题 0 分 |
| 2 | crosswalk `stop_distance` | 0.10→**1.25** | 停车 0.26m <1.0 → 扣 20（若规则触发） |
| 3 | traffic_light `stop_distance` | 0.10→**1.25** | 红灯停车贴线/压线 → 扣 20 |
| 4 | crosswalk `stop_timeout` | 3.0→**30.0** | 行人 0.5m/s 横穿需 16s > 3s → 3s 后放行 → 硬失败 100 |
| 5-8 | scene_speed_limit `crosswalk_enabled / forward 8 / backward 5 / limit 0.7` | — | 7am/7pm 减速带区超速（评分 ≤1.0）→ 扣分 |
| 9-12 | scene_speed_limit `traffic_light_enabled / forward 8 / backward 8 / limit 0.7` | — | 6am/6pm 减速带区超速；backward<8 时尾部缺口 0.8m 超速扣 20-40 |

### 🟡 强烈建议（有它更稳，防御实车日志实锤的坑）—— 2 项

| # | 参数 | 原始→新值 | 防御什么 |
|---|------|----------|---------|
| 13 | `min_stop_distance_obstacle` | 0.0→**0.8** | 实车横穿行人被感知为 **UNKNOWN** → crosswalk 规则不触发 → 停车由 speed_decider 兜底（原始 0 = 停行人前 0m，实测 0.26m 扣 20）。0.8 后停车 = 1.06~1.42m 达标 |
| 14 | crosswalk `expand_s_distance` | 0.0→**6.0** | 实测 PEDESTRIAN 行人在横道旁 l=-3.5（expand=0 不含）→ 扩大检测区帮 crosswalk 触发；同时提前 6m 减速防急刹 |

### 🟢 可选（锦上添花，现场按需）—— 3 项

| # | 参数 | 原始→新值 | 防御什么 |
|---|------|----------|---------|
| 15 | `planning_upper_speed_limit` | 5.0→**4.5** | 5.0 本身合法（∈[1.5,5.1]），仅防"越界 5.1 判 0"的极端风险，属保险 |
| 16 | crosswalk `stop_strict_l_distance` | 1.0→**4.0** | 防 SKIP 放行（需 decel≥4 才触发；我们 cruise 2.5 低速 + 提前减速，实际不会触发 → 可不改） |
| 17 | crosswalk `stop_loose_l_distance` | 1.5→**5.0** | 同上，弱停档保护；低速下风险低 → 可不改 |

> ⚠️ **明确不改**：`max_stop_deceleration`（4.0，调大允许急刹扣加速度）、`is_stop_for_pedestrain`（true 也只认 PEDESTRIAN，对 UNKNOWN 无效）、**control 全部**（实车已验证无超调，动了反而引入风险）。

## 三、现场决策树（首圈验证 → 选方案）

```
开始（8/7 上午第一场）
│
├─ 默认上传 PLAN_C（首选）
│
├─ 首圈观察（DreamView + 评分页）：
│
├─ ① 减速带区速度？
│     ├─ ≤1.0（约 0.5-0.7）→ 限速题 OK ✅
│     └─ 超速或扣分 → 切 PLAN_D（limit 0.6 / forward 10）
│
├─ ② 人行道/红灯停车距离？
│     ├─ 1.0~1.5m → 停车达标 ✅（crosswalk 触发 或 min_stop 兜底生效）
│     ├─ <1.0m（贴线）→ 说明兜底不足 → min_stop 0.8→0.9（现场改一行）
│     └─ >1.5m（停太远）→ min_stop 0.8→0.6（现场改一行）
│
├─ ③ 巡航峰值？
│     ├─ ≤3.0556（期望 ≤2.5）→ OK ✅
│     └─ 偶发超速 → cruise 2.5→2.2
│
├─ ④ 全程加速度？
│     ├─ 无急刹（-3 边界外）→ OK ✅
│     └─ 有急刹扣分 → 检查减速起点（forward 是否生效）→ PLAN_D
│
├─ ⑤ 想减少变量？
│     └─ 首圈全达标 → 可降级 PLAN_A（crosswalk 已确认正常）
│
└─ 任一题异常 → 现场微调（改单行 → 只重启 Planning 模块，不用编译）
```

**现场微调命令**（只改配置 → 只重启 planning，不用编译不用 use default）：
```bash
ssh car "sed -i 's/min_stop_distance_obstacle=0.8/min_stop_distance_obstacle=0.9/' /apollo/modules/planning/planning_component/conf/planning.conf"
# 改完重启 planning（DreamView 或 cyber_launch 操作）
```

## 四、"限速扣 1 分" 情报解读与应对

**可能根源**（按概率）：
1. **进区减速瞬间加速度**略超 -3（2.5→0.7 若减速太陡）→ 扣 1 分/帧 → **应对**：forward 8→10（更早更缓）或 limit 0.7→0.6
2. **区段边缘**（车头进评分区前未降到 ≤1.0，或车尾未出区就恢复加速）→ **应对**：backward 已覆盖（5/8），若仍扣 → 再加 1m
3. **巡航偶发超速**（控制过冲）→ **应对**：cruise 2.5 实测峰值 2.456 无超调，已安全；若仍扣 → 2.2

**决策**：扣 1 分（≤2 分）**可接受**，不要为了 1 分过度调参引发其他题风险。只有连续多扣才切 PLAN_D。
